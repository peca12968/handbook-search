# Vector Sieve｜加上文件篩選後，向量搜尋還找得到答案嗎？

手冊檢索器要為指定版本找出距離查詢最近的五個段落。若先在整座 Faiss HNSW 索引找候選、再篩掉不適用的版本，符合條件的段落可能連候選都沒進入。工具把這個流程與「每組各建索引」放在同一份資料上，逐題和精確搜尋比對。

## 重現一次漏召回

使用 Python 3.12 與 CPU。示範生成 2,048 個 32 維向量，涵蓋 16 個主題，每個主題有 120 個通用段落、8 個地區段落。每個主題用相同的查詢向量分別查兩種版本。這是刻意建立的分布，用來重現候選不足，並未衡量語言模型對真實文件的理解能力。

```sh
python -m pip install --only-binary=:all: -r requirements.txt
python demo.py --export dataset.json
python sieve.py dataset.json --k 5 --candidates 32 --expansion 64
python -m unittest -v
```

本機以 32 個候選查地區版時，16 題全部回傳空清單；在地區索引內搜尋則找回 80 個精確前五名。報告也列出通用版查詢，方便辨別特定族群的失敗。執行示範會再試 128 個候選，觀察增加候選數後是否仍漏掉段落。HNSW 的實際召回會受索引與執行環境影響。[Faiss 索引說明](https://github.com/facebookresearch/faiss/wiki/Faiss-indexes)

## 匯入自己的模型輸出

JSON 內的 `items` 與 `queries` 都是陣列。每列提供其集合內唯一的字串 `id`、要比對的 `group` 及已編碼的數值 `vector`。所有向量維度須一致，座標轉成 float32 建索引。此工具使用平方歐式距離，若模型使用餘弦相似度，請先將文件與查詢向量都正規化為單位長度。

每題會列出符合條件的總數、精確前 k 名、各方案取回的候選數、合格候選數、最終 ID 與 recall。候選數是索引回傳筆數。兩種方案都用相同距離重排最終候選，對照組則以 float64 在符合條件的所有 float32 座標上重新計算距離。分組方案要維護每個使用中群組的索引，報告沒有量測建置成本或延遲。

召回率分母為 `min(k, 合格項目數)`。邊界同距離的候選可以互換，但不能藉此補回遺漏的更近項目。無合格資料時回傳 `null`。測試逐題以另一套純 Python 距離排序核對示範，並枚舉可接受的同分答案集合核對評分。[評估程式](sieve.py) · [測試](test_sieve.py)

本專案使用 AI 輔助開發，隨附向量皆為合成資料。
