# Batch Parity｜同一張工單，換個批次還會得到相同分數嗎？

推論服務把長短不同的客服工單併成一批後，一段只有一個 token 的輸入，原先得到 4.0 分，補齊為五格卻只剩 0.8 分。預測類別仍相同，只比對類別的測試會放過這個錯誤。Batch Parity 使用 ONNX Runtime 的 CPU 執行器實際比較每一類的分數。

## 重現四種模型

使用 Python 3.12，在專案目錄執行以下指令。示範會在暫存目錄產生四個可執行的 ONNX 模型。

```sh
python -m pip install --only-binary=:all: -r requirements.txt
python model_demo.py
python -m unittest -v
```

| 模型計算方式 | 實際觸發的檢查 |
| --- | --- |
| 依有效 token 數平均 | 兩筆樣本共六項檢查都通過 |
| 將補齊位置算進平均的分母 | 補齊後分數下降，預測類別仍相同 |
| 減去同批樣本的平均 | 改變同批成員後分數改變，其中一筆的預測類別也改變 |
| 沿批次軸做前綴加總 | 換同批成員及調換排列都會改變分數 |

## 檢查自己的分類模型

準備 JSON 陣列，每筆包含唯一的字串 `id` 與非空的整數 `tokens`，例如 `[{"id":"returns","tokens":[1]},{"id":"delivery","tokens":[2,2,1]}]`。模型須接受 int64 的 `input_ids` 與 `attention_mask`，支援變動的批次大小、序列長度，並輸出每筆一列的浮點類別分數。

```sh
python check.py classifier.onnx samples.json --output logits --pad 0 --extra 2 --atol 0.00001 --rtol 0.00001
```

工具分三步比對同一筆樣本。先以單筆輸入比較原長與補齊後的分數；再固定補齊寬度，將單筆放入混合批次；最後保持所有成員與寬度固定，將批次輪轉一格，讓每筆樣本都移到不同位置。每一項測試按樣本 ID 對齊輸出。

報告保留超出容差的類別索引、最大絕對差、該類的兩個分數，以及第一名是否改變。逐類允許差值為 `atol + rtol × abs(參考分數)`。結束碼 0 表示這批樣本通過，1 代表量到差異，2 代表輸入、模型或執行出錯。這組測試檢查批次配置下的一致性，判斷分類品質另需標註樣本。[推論檢查](check.py) · [重現測試](test_parity.py)
